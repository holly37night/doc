3. 図から読み取れるポイント

  • frontend を同じ VPC に置いたことで、SSMトンネルが不要になりました。これまでローカルPCから RAG API（内部ALB）へ届かず SSM ポートフォワードが必要でしたが、frontend が VPC 内にいるため直接到達できます。ユーザーは ALB の1つの URL を開くだけです。
  • RAG コアとアプリは別クラスタですが、ネットワークは同じ VPC です。クラスタを分けたのはデプロイとスケールを独立させるためで、通信は VPC 内の内部 ALB で完結しています。
  • VPC エンドポイントは未作成です。そのため S3 / DynamoDB / SQS / ECR / Secrets Manager / CloudWatch へのアクセスはすべて NAT Gateway 経由になります。通信量が増える場合は S3・DynamoDB の Gateway エンドポイント（無料）を追加すると NAT のデータ処理料金を削減できます。
  • dbhub だけが図の中で切れています。接続先の社内DB は別VPC（172.31.0.0/16）にあり、現VPC（10.0.0.0/16）とのピアリングがありません。CIDR は重複していないのでピアリング自体は可能ですが、共有ネットワークの変更になるためネットワーク担当の承認が必要です。
  • 参考: 同アカウントに dev-itssgm-lam-aimanager-to-rag / dev-itssgm-lam-aimanager-to-s3 という Lambda が2つありますが、VPC 未接続・環境変数なし・イベントソース未設定で、現在の経路には組み込まれていないため図には含めていません。
