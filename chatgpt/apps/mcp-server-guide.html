01概要

東横INN公式ホテル検索APIを呼び出すMCPツールを1つだけ提供する、単独のMCPサーバー。既存の統合MCPサーバー（backend/mcp/server）とは別プロセス・別イメージで動作し、AWS ECS (Fargate) 上で稼働する。LLM（Gemini等）から function calling でツールを呼び出すと、検索条件にもとづいて空室のあるホテル・部屋・プラン・料金が実データで返る。

1.1 提供ツール

ツール名説明引数
search_hotels 条件に合う空室ありホテル・部屋・プラン・料金を公式APIから検索する criteria（必須）/ conversation_id / user_id

criteria に指定できる項目

キー説明
destination目的地・エリア名（例: 新宿, 大阪）
landmarkランドマーク名（任意。座標を解決して距離順に並べる）
hotel_nameホテル名の一部（任意。指定するとホテル名で優先検索する）
checkin_dateチェックイン日（YYYY-MM-DD）
nights / guests / rooms宿泊数 / 人数 / 部屋数（既定はいずれも 1）
smokingnon_smoking または smoking（任意）

1.2 公開エンドポイント

メソッドパス用途
GET/healthヘルスチェック（ALB / ECS のヘルスチェック先）
GET/toolsツール一覧（REST）
POST/tools/callツール呼び出しプロキシ（REST）
POST/mcpMCP Streamable HTTP（ChatGPT など新しいMCPクライアント用）
GET/legacy/sseMCP SSE（従来のMCPクライアント互換）

MCPクライアントから接続する場合は /mcp（Streamable HTTP）を使う。REST の /tools /tools/call は MCP を介さない簡易呼び出し用で、動作確認や自前のアプリから叩く場合に使う。

02接続URL

2.1 HTTPS（CloudFront）— インターネットから

ChatGPT アプリ登録など、外部サービスから接続する場合はこちら。ベースURLは https://d3v8770g38r8os.cloudfront.net。

用途URL
ヘルスチェックhttps://d3v8770g38r8os.cloudfront.net/health
ChatGPT等への登録用（MCP）https://d3v8770g38r8os.cloudfront.net/mcp
ツール一覧（REST）https://d3v8770g38r8os.cloudfront.net/tools
ツール呼び出し（REST）https://d3v8770g38r8os.cloudfront.net/tools/call
ブラウザで開いたときのエラーは正常

/mcp をブラウザで直接開くと {"code":-32600,"message":"Not Acceptable: Client must accept text/event-stream"} が返るが、異常ではない。MCP の Streamable HTTP は Accept: text/event-stream を要求するのに対し、ブラウザは Accept: text/html,... を送るため仕様どおり拒否される。ChatGPT などのMCPクライアントは正しいヘッダーを送るので問題ない。ブラウザで疎通を見たい場合は /health か /tools を開くこと。

2.2 HTTP（内部ALB）— 社内ネットワークから

ベースURLは http://internal-hotel-info-mcp-alb-1843477390.ap-northeast-1.elb.amazonaws.com。内部ALBのため、社内ネットワークまたはVPC内からのみ到達できる。/health /tools /tools/call /mcp が利用できる。

bash内部ALB 経由の呼び出し例
ALB=internal-hotel-info-mcp-alb-1843477390.ap-northeast-1.elb.amazonaws.com

curl http://$ALB/health
curl http://$ALB/tools

cat > req.json << 'EOF'
{"name":"search_hotels","arguments":{"criteria":{"destination":"大阪","checkin_date":"2026-08-20","nights":1}}}
EOF

curl -X POST http://$ALB/tools/call -H "Content-Type: application/json" --data-binary @req.json

2.3 ローカル（Docker）

http://localhost:8011。/health /tools /tools/call /mcp /legacy/sse の構成は ECS と同じ。ホストポートは環境変数 HOTEL_INFO_MCP_PORT で変更できる（既定 8011）。

2.4 接続時の注意点

  • CloudFront（HTTPS）はインターネット公開・認証なし。動作確認用の一時構成であり、確認後は停止すること
  • 内部ALB（HTTP）は社内ネットワークまたは VPC 内からのみ到達できる
  • 独自ドメインは使っていない。CloudFront 既定の *.cloudfront.net 証明書を利用しているため、ACM 証明書の取得や Route 53 の設定は不要
  • 日本語を含むリクエストはシェルの引数エンコーディングで壊れることがあるため、JSON はファイルに書いて --data-binary @file で渡すこと

06AWS構築手順（実行したコマンド）

以下は実際に実行したコマンドを順番どおりに記載したもの。すべて --region ap-northeast-1 で実行する。

  1. 手順 0前提
    • AWS CLI v2 が設定済みで、ap-northeast-1 に対する操作権限があること
    • Docker Desktop が起動していること
    • Fargate は linux/amd64 のため、ビルド時に --platform linux/amd64 が必須
  2. 手順 1Secrets Manager にシークレットを作成

    公式APIキーと thhtldb のパスワードを登録する。

    bashcreate-secret
    # .env から公式APIキーを取り出し、JSON を組み立てて登録する
KEY=$(grep "^OFFICIAL_API_KEY=" .env | cut -d= -f2- | tr -d "'\"")
python -c "
import json,sys
open(sys.argv[2],'w').write(json.dumps({'official_api_key': sys.argv[1], 'thhtldb_pass': 'kaizen'}))
" "$KEY" secret.json

aws secretsmanager create-secret \
  --name hotel-info-mcp \
  --description "hotel-info-mcp-server secrets" \
  --secret-string file://secret.json \
  --region ap-northeast-1

rm -f secret.json

    出力された ARN（例: arn:aws:secretsmanager:ap-northeast-1:277019134452:secret:hotel-info-mcp-ON4fnx）をタスク定義に設定する。末尾のランダム6文字を含めた名前が必要。

  3. 手順 2IAM 実行ロールを作成

    ECR からのイメージ取得、CloudWatch へのログ出力、シークレット読み取りを行うロール。

    bashhotel-info-mcp-execution-role
    # 信頼ポリシー
cat > trust.json << 'EOF'
{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"ecs-tasks.amazonaws.com"},"Action":"sts:AssumeRole"}]}
EOF

# ロール作成（description に日本語は使えない。ASCIIのみ）
aws iam create-role \
  --role-name hotel-info-mcp-execution-role \
  --description "ECS task execution role for hotel-info-mcp-server" \
  --assume-role-policy-document file://trust.json \
  --region ap-northeast-1

# AWS管理ポリシーをアタッチ
aws iam attach-role-policy \
  --role-name hotel-info-mcp-execution-role \
  --policy-arn arn:aws:iam::aws:policy/service-role/AmazonECSTaskExecutionRolePolicy

# シークレット読み取り権限を追加
cat > secret-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "secretsmanager:GetSecretValue",
      "Resource": "arn:aws:secretsmanager:ap-northeast-1:277019134452:secret:hotel-info-mcp-*"
    }
  ]
}
EOF

aws iam put-role-policy \
  --role-name hotel-info-mcp-execution-role \
  --policy-name hotel-info-mcp-secrets \
  --policy-document file://secret-policy.json

  5. 手順 4CloudWatch ロググループを作成
    先に作成しておくこと

    AmazonECSTaskExecutionRolePolicy には logs:CreateLogGroup が含まれないため、タスク定義側の自動作成（awslogs-create-group: true）は失敗する。

08構築時に発生した問題と対処

8.1 タスクが起動できない（TaskFailedToStart）

errorResourceInitializationError
ResourceInitializationError: ... AccessDeniedException: User: ...hotel-info-mcp-execution-role
is not authorized to perform: logs:CreateLogGroup

原因: AmazonECSTaskExecutionRolePolicy には logs:CreateLogStream と PutLogEvents はあるが logs:CreateLogGroup は含まれない。タスク定義の awslogs-create-group: true が失敗していた。

対処: ロググループを事前作成し（手順4）、タスク定義から awslogs-create-group を削除した。実行ロールに logs:CreateLogGroup を足す方法もあるが、権限を最小限に保つため前者を選んだ。

8.2 ECR ログインが 400 Bad Request（PowerShell）

原因: Windows PowerShell 5.1 では aws ecr get-login-password | docker login --password-stdin のパイプでトークンが壊れる。

対処: 一時ファイルに ASCII・改行なしで書き出し、cmd のリダイレクトで stdin に流す方式に変更した。

powershell一時ファイル経由の docker login
$TokenFile = [System.IO.Path]::GetTempFileName()
$Token = aws ecr get-login-password --region $Region
[System.IO.File]::WriteAllText($TokenFile, $Token, (New-Object System.Text.ASCIIEncoding))
cmd /c "docker login --username AWS --password-stdin $Registry < ""$TokenFile"""
Remove-Item $TokenFile -Force

8.3 公式APIが 403 Forbidden（検索結果が常に0件）

logsearch-service のログ
[search-service] rooms error hotel=00298: Client error '403 Forbidden' for url '.../access-token'

原因: API Gateway に WAF（デフォルト Block ＋ IP許可リスト）が付いており、ECS の NAT ゲートウェイ IP 35.79.200.36 が未登録だった。APIキー自体は Secrets Manager と .env で一致しており、認証の問題ではなかった。thhtldb からのホテルコード取得は成功していたため、ネットワーク経路も問題なかった。

対処: IPセット dev-commapi-wafipsets-ToyokoInnHpApi に 35.79.200.36/32 を追加。

8.4 /mcp が 500「Task group is not initialized」

errorRuntimeError
RuntimeError: Task group is not initialized. Make sure to use run().

原因: Starlette の mount() はサブアプリの lifespan を実行しない。streamable_http_app() をマウントしただけでは、Streamable HTTP のセッションマネージャが起動していない状態になる。

対処: FastAPI 側の lifespan でセッションマネージャを明示的に起動する。

pythonapp/main.py — lifespan
@contextlib.asynccontextmanager
async def lifespan(_app: FastAPI):
    async with contextlib.AsyncExitStack() as stack:
        session_manager = getattr(mcp, "session_manager", None)
        if session_manager is not None:
            await stack.enter_async_context(session_manager.run())
        yield

app = FastAPI(title="Hotel Info MCP Server", lifespan=lifespan)
マウント順序

streamable_http_app() の内部パスは /mcp、sse_app() は /sse と /messages。同じ "/" に二重マウントすると先に登録した方が全パスを受けてしまうため、先に app.mount("/legacy", mcp.sse_app())、後に app.mount("/", mcp.streamable_http_app()) の順で登録している。

8.5 CloudFront が 504 Gateway Timeout

原因: CloudFront の VPCオリジンが使う ENI から ALB への通信が、ALB のセキュリティグループで許可されていなかった。

対処: ALB のセキュリティグループに、VPCオリジンのセキュリティグループ（CloudFront-VPCOrigins-Service-SG）からの 80/tcp を明示的に許可する。

bashSG参照による許可
aws ec2 authorize-security-group-ingress --group-id sg-09fb06b23b250f8ab \
  --protocol tcp --port 80 --source-group sg-0d43c98fe10d3b5cb --region ap-northeast-1

ENI の IP が許可済みの CIDR（172.31.0.0/16）に含まれていても、セキュリティグループ参照による許可が必要だった。なお切り分け時は curl のタイムアウトに注意する。CloudFront は OriginReadTimeout（今回60秒）を待ってから 504 を返すため、curl -m 25 などで打ち切ると「応答なし」に見えて原因を誤認しやすい。

8.6 その他の注意点

事象原因と対処
logGroupName が C:/Program Files/Git/ecs/... になるGit Bash のパス変換。/ で始まる引数は PowerShell で実行する
IAM create-role の description でエラーdescription に日本語（マルチバイト）は使えない。ASCII のみ

9.4 運用上の注意

  • CloudFront は認証なしでインターネット公開されている。ChatGPT アプリの動作確認用の一時構成であり、確認後は 9.2 の手順で停止すること。継続運用する場合は WAF による IP 制限やカスタムヘッダー認証を検討すること
  • ECS の NAT ゲートウェイ IP（35.79.200.36）が変わった場合、WAF への再登録が必要。NATを作り直したり別サブネットへ移す際は必ず確認すること
  • 公式APIキー・thhtldbパスワードを変更した場合は Secrets Manager を更新し、--force-new-deployment でタスクを入れ替える
  • ALB は内部向け（internal-）。インターネットに公開する場合は public サブネットと HTTPS リスナー（ACM証明書）の追加が必要
