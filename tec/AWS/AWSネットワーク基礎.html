CHAPTER 1AWSネットワークの全体像

AWSのネットワークは6つの要素に分けて考えると整理しやすくなります。街に例えると、それぞれの役割がイメージしやすくなります。

#要素役割街に例えると
1IP / CIDRIPアドレスと範囲住所
2VPC / Subnetネットワークの作成と分割大きな土地 / 区画
3Route Table通信経路案内標識
4Gateway外部ネットワークとの接続出入口
5Security（SG / WAF）アクセス制御と通信の保護警備員
6ACMHTTPS用証明書の管理（通信を暗号化する鍵の管理）

通信を確認する順番

宛先IPどこへ？→ 一致するRouteどの道？→ 通るGateway・接続どの出入口？→ SG / WAF等の許可通してよい？

考え方の順番です。実際のパケット処理順序を厳密に示すものではありません。

CHAPTER 2IPアドレスとCIDR

IPアドレスと2進数

IPv4アドレスは32bitで、8bit × 4つに区切って10進数で表記します。各bitには右から 1, 2, 4 … 128 の重みがあります。

CIDRとサブネットマスク

/24 は「先頭24bitがネットワーク部」という意味です。残りのbit（ホスト部）で個々のアドレスを表します。

CIDRサブネットマスクIP数ホスト部のbit数
/16255.255.0.065,536
/24255.255.255.0256
/25255.255.255.128128
/26255.255.255.19264
/27255.255.255.22432
/28255.255.255.24016
/32255.255.255.2551
ポイント：「/」の数値が1増えるとアドレス数は半分になります（ホスト部が1bit減るため）。/32 は単一のIPアドレスです。

CHAPTER 3VPCとSubnet

VPC はAWS上の仮想ネットワーク、Subnet はVPCのIP範囲を分割した区画です。例えば VPC 10.0.0.0/16 は 10.0.0.0～10.0.255.255（65,536アドレス）を持ち、これを /24 のSubnetに切り分けて使います。

SubnetAZ-AAZ-C主な配置
Public10.0.1.0/2410.0.2.0/24ALB
Private10.0.11.0/2410.0.12.0/24ECS
DB10.0.21.0/2410.0.22.0/24RDS
RULE 1

Subnetは必ず1つのAZに所属

1つのSubnetが複数のAZにまたがることはありません。

RULE 2

複数AZに分散して可用性UP

同じ役割のSubnetをAZごとに用意します。

RULE 3

Public/Privateはルートで決まる

IPの数字ではなく、主にルートテーブルの設定（IGWへの経路があるか）で決まります。

04

CHAPTER 4ルートテーブル

ルートテーブルは通信の案内標識です。「この宛先（Destination）ならこの転送先（Target）へ」というルールの一覧です。

Destination（宛先）Target（転送先）意味
10.0.0.0/16localVPC内部の通信
10.1.0.0/16pcx-xxxxVPC Peering 先のVPCへ
0.0.0.0/0igw-xxxx他に一致しないIPv4通信をIGWへ

例：宛先 10.1.2.20 はどこへ行く？

Destination一致する？プレフィックス長結果
10.0.0.0/16不一致/16—
10.1.0.0/16一致/16採用 → Peeringへ
0.0.0.0/0一致/0より具体的なルートがあるので使わない
最長プレフィックス一致：複数のルートに一致したときは、「/」の数値が大きい（範囲が狭く具体的な）ルートが優先されます。

CHAPTER 5Internet GatewayとNAT Gateway

IGW

Internet Gateway

VPCとインターネットの出入口。VPCにアタッチします。公開ALBなどの通信に利用。

NAT GW

NAT Gateway

Private Subnetから外へ出る通信を中継。通常のパブリックNAT GatewayはPublic Subnetに置きます。

IGWNAT Gateway
置き場所VPCにアタッチPublic Subnet（パブリックNATの場合）
通信の向きインターネット ⇄ VPCPrivate → インターネット（内側から開始）
主な用途公開ALBなどの受信・送信ECSが外部APIを呼ぶ、パッチ取得など

CHAPTER 6その他のネットワーク接続

覚え方：VGW＝VPN、Peering＝VPC同士、Endpoint＝AWSサービスへの近道。

VGW（Virtual Private Gateway）

Site-to-Site VPNなどで使う、AWS側のゲートです。

VPC Peering

VPC同士をプライベートIPで接続します。ただし推移的ルーティングは不可です。

VPC Endpoint

対応するAWSサービスへ、インターネットを経由せずプライベートに接続します。

接続つなぐ相手使う場面
VGW社内ネットワーク（VPN）オンプレミスとVPCを安全に接続
VPC Peering別のVPC少数のVPC同士をプライベートIPで接続
TGW多数のVPC・拠点接続数が多いときのハブ
VPC EndpointAWSサービスPrivateからS3等へインターネットを通らずに接続

CHAPTER 7セキュリティ（SG / WAF / Web ACL / ACM）

SG

Security Group

IP・ポートなどで通信を許可する仮想ファイアウォール。

WAF

Web Application Firewall

SQLインジェクション、XSSなどのWeb攻撃を防御。

WEB ACL

Web Access Control List

WAFに設定するルールの集合。特定IPのブロック、SQLi・XSS対策、大量アクセス制限など。

ACM

AWS Certificate Manager

SSL/TLS証明書を管理。ALBのHTTPSなどで使用。

SG設定例

方向プロトコルポートSource
InboundTCP443203.0.113.10/32

203.0.113.10 は説明用のIPアドレスです。

使い分け：ACM＝暗号化、WAF＝Web攻撃対策、SG＝ネットワーク通信の許可。

CHAPTER 8IP制御できる場所

「特定のIPだけ許可したい」とき、どこで何を使うかの一覧です。

場所IP制御方法
WAF / Web ACL直接できるIP SetによるAllow / Block
ALB直接できるSGで送信元IPを制限
API GatewayできるResource Policy / WAF（APIタイプによる）
VPC Endpoint種類によるEndpoint Policy / SG等
VPC Peering組み合わせRoute + SG + NACL
IGW間接的直接ではなくSG / NACL / Route等で制御
NAT Gateway間接的Routeで経路を決め、細かい宛先制御はFirewall等
ACMなしIP制御機能はない
SG の例

HTTPS / TCP 443 / Source 203.0.113.10/32

WAF の例

203.0.113.10/32 のみ許可、その他はBLOCK

  • /32 は単一のIPv4アドレス。
  • IGW自体に一般的なIP許可リストを直接設定するわけではありません。
  • Interface EndpointにはSGを使えますが、Gateway EndpointにSGを直接付けることはありません。
  • Endpoint Policyは主にAWSサービスへのアクセス権限を制御します。

KEY POINTS最重要ポイント

どこにあるか

IP / CIDR / VPC / Subnet

住所・範囲・土地・区画を決める要素。

どう通信するか

Route Table / Gateway / Peering / Endpoint

宛先ごとの道順と、外部・他VPC・AWSサービスへの経路。

どう制御・保護するか

SG / NACL / WAF / ACM

通信の許可、Web攻撃の防御、HTTPSによる暗号化。
