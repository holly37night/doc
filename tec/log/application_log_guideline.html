アプリケーションログ管理ガイドライン

Webアプリケーション、API、バッチ、AWS Lambdaなどで共通利用できる、 ログレベル別の記録基準と構造化ログの設計方針をまとめたガイドラインです。

1. 基本方針 2. レベル一覧 3. レベル別詳細 4. 共通項目 5. JSON例 6. 禁止情報 7. 判断基準

1. 基本方針

ログは、障害調査だけでなく、監視、監査、性能分析、業務処理の追跡に使用します。 そのため、単なる文章ではなく、検索しやすい構造化ログとして出力することを推奨します。

ログレベルは「例外が発生したか」ではなく、「利用者や業務処理にどの程度の影響があったか」で判断します。
パスワード、アクセストークン、APIキー、カード情報などの機密情報は、 ログレベルに関係なく出力してはいけません。

2. ログレベル別一覧

ログレベル 用途 入れなければいけないもの 入れたほうがよいもの 代表例
TRACE 処理を非常に細かく追跡する 原則なし。本番では通常無効 メソッド開始・終了、ループ、内部状態、詳細な変数 検索処理の各ステップ
DEBUG 開発・調査時の詳細確認 処理名、対象ID、主要な分岐結果 入力値、検索条件、取得件数、中間結果、API通信概要 予約検索条件の生成
INFO 正常な業務・システム処理の記録 処理名、処理結果、対象ID、完了状態 ユーザーID、処理件数、処理時間、変更前後の状態 予約登録完了、バッチ完了
WARN 継続可能だが注意が必要 発生事象、影響、対象ID、継続・代替処理の有無 リトライ回数、閾値、タイムアウト、復旧内容 APIタイムアウト後のリトライ
ERROR 要求された処理が失敗 失敗処理、エラー内容、対象ID、例外、影響範囲、追跡ID スタックトレース、HTTP/DBエラー、ロールバック結果 DB更新失敗、予約登録失敗
FATAL / CRITICAL サービス継続が困難 原因、発生箇所、影響範囲、サービス状態、例外 停止対象、復旧手順、通知先、フェイルオーバー結果 DB接続不可で起動失敗

3. ログレベル別の詳細

TRACE

処理内部を1ステップずつ追跡するためのログです。

推奨

  • メソッド・関数の開始と終了
  • 条件分岐の判定結果
  • ループ内の各処理
  • 詳細な中間変数
  • 内部状態の遷移

運用: 出力量が多いため、本番環境では原則無効にします。

DEBUG

開発中や障害調査時に、処理内容を確認するためのログです。

必須

  • 処理名
  • 対象を識別するID
  • 主要な分岐・処理結果

推奨

  • 入力パラメータ
  • 検索条件、取得件数
  • 外部APIの要求・応答概要
  • キャッシュのヒット・ミス
  • SQL実行時間

INFO

正常に完了した業務処理やシステム処理を記録します。

必須

  • 処理名
  • 処理結果
  • 対象ID
  • 成功・完了状態

推奨

  • リクエストID、ユーザーID
  • 予約番号などの業務ID
  • 処理件数、処理時間
  • ステータス変更前後
  • 外部サービス名、実行元

WARN

想定外の状態ですが、処理を継続できる場合に使用します。

必須

  • 何が起きたか
  • 対象ID
  • 影響内容
  • 処理継続・代替処理の有無

推奨

  • リトライ回数と上限
  • タイムアウト時間、閾値
  • 外部APIのステータス
  • デフォルト値や復旧内容

ERROR

要求された処理が失敗し、正常な結果を返せない場合に使用します。

必須

  • 失敗した処理
  • エラー内容、例外名
  • 対象ID、影響範囲
  • リクエストIDまたはトレースID

推奨

  • スタックトレース
  • HTTP・DBエラーコード
  • リトライ可否
  • ロールバック結果
  • エラー分類、対応方法

FATAL / CRITICAL

アプリケーションやサービスを継続できない重大障害に使用します。

必須

  • 継続不能となったサービス・処理
  • 原因、発生箇所
  • 影響範囲、サービス状態
  • 例外情報

推奨

  • 停止したコンポーネント
  • 再起動・復旧方法
  • 通知先
  • フェイルオーバー結果

4. すべてのログに共通して入れる項目

項目 必須度 内容
timestamp必須ログ発生日時。タイムゾーンを含める
level必須TRACE、DEBUG、INFO、WARN、ERRORなど
service必須サービス名・アプリケーション名
environment必須production、staging、development
message必須何が起きたかを簡潔に記述
requestId必須1リクエストを追跡するID
traceId推奨複数サービス間を追跡するID
userId推奨実行ユーザー。内部IDや匿名化IDを利用
businessId推奨予約番号、注文番号、会話IDなど
component推奨Controller、Service、Repositoryなど
action推奨実行した処理名
result推奨success、failure、partialなど
durationMs推奨処理時間
errorTypeERROR時必須例外・エラーの分類
errorCodeERROR時推奨システム独自のエラーコード
stackTraceERROR時推奨例外発生箇所
host推奨EC2、ECSタスク、コンテナなどの識別子
version推奨アプリケーションのバージョン
clientIp条件付き必要性と個人情報管理を考慮して記録

5. 推奨するJSON形式

CloudWatch Logs、Datadog、Splunk、OpenSearchなどで検索・集計しやすくするため、 JSON形式の構造化ログを推奨します。

INFOログの例

{
  "timestamp": "2026-07-31T16:30:00.123+09:00",
  "level": "INFO",
  "environment": "production",
  "service": "reservation-api",
  "version": "1.5.2",
  "component": "ReservationService",
  "action": "createReservation",
  "message": "Reservation created",
  "requestId": "req-abc123",
  "traceId": "trace-xyz789",
  "userId": "456",
  "reservationId": "RSV000123",
  "hotelId": "001",
  "result": "success",
  "durationMs": 325
}

ERRORログの例

{
  "timestamp": "2026-07-31T16:30:00.123+09:00",
  "level": "ERROR",
  "environment": "production",
  "service": "reservation-api",
  "component": "ReservationService",
  "action": "createReservation",
  "message": "Reservation creation failed",
  "requestId": "req-abc123",
  "traceId": "trace-xyz789",
  "reservationId": "RSV000123",
  "errorType": "DatabaseException",
  "errorCode": "DB-001",
  "retryable": false,
  "rollback": "success",
  "stackTrace": "DatabaseException at ReservationRepository.java:125"
}

6. ログに出してはいけない情報

対象 対応
パスワード絶対に出力しない
アクセストークン出力しない
APIキー・シークレットキー出力しない
セッションID・Cookie原則出力しない。必要な場合はハッシュ化・部分化
クレジットカード番号・セキュリティコード絶対に出力しない
マイナンバー・身分証番号出力しない
氏名・住所・電話番号・メールアドレス必要最小限とし、原則マスキング
リクエストボディ全体認証情報・個人情報を除外し、必要項目だけ記録
外部APIレスポンス全体必要なステータスや識別子だけ記録
SQLのバインド値個人情報や機密情報を含む可能性があるため原則制限

マスキング例

email=s***a@example.com
phone=090-****-1234
cardNumber=************1234

7. ログレベルの判断基準

正常に完了した
→
INFO
開発・調査用の詳細情報
→
DEBUG または TRACE
想定外だが処理は継続できる
→
WARN
要求された処理が完了できなかった
→
ERROR
サービスやシステムを継続できない
→
FATAL / CRITICAL
ユーザーの入力ミスや、存在しない予約番号の指定など、 仕様上想定される事象は必ずしもERRORではありません。 業務上の影響に応じてINFOまたはWARNを使用します。
