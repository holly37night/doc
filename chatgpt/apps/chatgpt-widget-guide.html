構成要素役割

ChatGPT が search_hotels を呼ぶ → 戻り値（structuredContent）がウィジェット内で window.openai.toolOutput として読まれる → React がカードを描画する。

2.5 ビルドと同梱

prebuilt/hotel-search-result.html は React と CSS をインライン化した自己完結HTML（外部からの読み込みは https://esm.sh の React のみ）。これを MCP イメージに app/widget/hotel-search-result.html として同梱し、リソースとして配信する。

注 — 本番での推奨

ウィジェットは React を https://esm.sh から動的 import するため、CSP で resource_domains に https://esm.sh を許可している。本番では Vite でビルドして完全インライン化し、外部CDN依存を無くすことを推奨する。

3.1 既存との差分（追加2点＋設定2点）

#差分内容
1 追加 ウィジェットを MCP リソースとして登録 ui://widget/hotel-search-result.html、MIME text/html;profile=mcp-app、CSPで esm.sh 許可
2 追加 search_hotels に _meta["openai/outputTemplate"] を付与 出力をウィジェットで描画する結線
3 設定 json_response=True /mcp の応答を SSE ではなく通常JSONで返す（CloudFront 等のプロキシ対策）
4 設定 transport_security（DNSリバインディング保護を無効化） ALB/CloudFront 経由で Host ヘッダがオリジンのDNS名になり、既定の保護で /mcp が 421 になるのを防ぐ

3.2 コード抜粋（app/main.py）

pythonリソース登録 + outputTemplate 結線
from mcp.server.fastmcp import FastMCP
from mcp.server.transport_security import TransportSecuritySettings

WIDGET_URI = "ui://widget/hotel-search-result.html"
WIDGET_MIME_TYPE = "text/html;profile=mcp-app"
WIDGET_HTML = (Path(__file__).resolve().parent / "widget" /
               "hotel-search-result.html").read_text(encoding="utf-8")

mcp = FastMCP(
    "Toyoko Inn Hotel Info MCP",
    json_response=True,
    transport_security=TransportSecuritySettings(enable_dns_rebinding_protection=False),
)

# (1) ウィジェットを MCP リソースとして登録
@mcp.resource(
    WIDGET_URI, name="ホテル検索結果ウィジェット", mime_type=WIDGET_MIME_TYPE,
    meta={
        "openai/widgetDescription": "空室ありホテルの一覧を、料金・プラン・予約ボタン付きのカードで表示します。",
        "openai/widgetPrefersBorder": True,
        "openai/widgetCSP": {"connect_domains": [], "resource_domains": ["https://esm.sh"]},
    },
)
def hotel_search_widget() -> str:
    return WIDGET_HTML

# (2) search_hotels に outputTemplate を付与（出力をウィジェットで描画）
@mcp.tool(
    meta={
        "openai/outputTemplate": WIDGET_URI,
        "openai/toolInvocation/invoking": "空室を検索しています…",
        "openai/toolInvocation/invoked": "検索結果を表示しました。",
    },
)
def search_hotels(criteria: dict, conversation_id: str = "", user_id: str = "guest-001") -> dict:
    return _post(f"{SEARCH_SERVICE_URL}/search/hotels",
                 {"conversation_id": conversation_id, "user_id": user_id, "criteria": criteria})

CloudFront（HTTPS）→ 内部ALB → ECS（ウィジェット同梱MCP）→ search-service → 公式API の全経路で、ウィジェット結線と実データ検索が成立することを確認した。

07構築時に発生した問題と対処

7.1 /mcp が 421「Invalid Host header」

原因: MCP の Streamable HTTP には DNS リバインディング保護があり、ALB/CloudFront（VPCオリジン）経由だと Host ヘッダがオリジンのDNS名になり、既定の許可ホストに弾かれる。/health（FastAPI の素のルート）は通るが /mcp だけ 421 になる。

対処: FastMCP 生成時に保護を無効化する。

pythonDNSリバインディング保護を無効化
mcp = FastMCP("Toyoko Inn Hotel Info MCP", json_response=True,
              transport_security=TransportSecuritySettings(enable_dns_rebinding_protection=False))

7.2 @mcp.tool(meta=...) / @mcp.resource(meta=...) が使えない

原因: 既存の mcp[cli]==1.9.1 はデコレータの meta= 引数に未対応。

対処: requirements.txt を mcp[cli]>=1.27.0 に更新（ビルド時は 1.29.0 が解決された）。/tools/call の REST プロキシは、デコレータ後の関数を getattr(fn, "fn", fn) で取り出して呼ぶよう修正。

7.3 プロキシ経由のストリーミング対策

CloudFront 経由でも安定するよう、/mcp の応答を SSE ではなく通常JSONで返す json_response=True を設定した。

参考 — 親手順書 8.5

「CloudFront が 504 Gateway Timeout」のとおり、内部ALBのSGが VPCオリジンのSG（CloudFront-VPCOrigins-Service-SG）からの 80/tcp を許可している必要がある。今回は既存設定で許可済みだった。

08運用

8.1 イメージを更新して反映する

bash再ビルド&プッシュ（手順2）→ 反映
aws ecs update-service --cluster hotel-info-mcp-cluster --service hotel-info-mcp-server \
  --force-new-deployment --region ap-northeast-1

8.2 停止・再開

必須

CloudFront による外部公開は認証がないため、動作確認が終わったら必ず停止すること。

bashECSタスクの停止・再開
# タスクを止める（Fargate課金が止まり、外部からも応答しなくなる）
aws ecs update-service --cluster hotel-info-mcp-cluster --service hotel-info-mcp-server \
  --desired-count 0 --region ap-northeast-1

# 再開する場合
aws ecs update-service --cluster hotel-info-mcp-cluster --service hotel-info-mcp-server \
  --desired-count 1 --region ap-northeast-1

外部公開だけを止めたい場合は、手順4と同じ方法で CloudFront の Enabled を false に戻す。
